# Бриф: создание регламента по СТО-34-003

## Цель
Сформировать **исполняемый регламент должности** — не пересказ файлов, а нормативный документ с алгоритмами.

## Структура документа (обязательные разделы)
1. Назначение и область применения  
2. Нормативные ссылки (минимум СТО-34-003)  
3. Термины и определения  
4. Сокращения  
5. Ответственность (кто исполняет каждый процесс)  
6. Организация работы — **основной раздел**: подраздел 6.x на каждый процесс  
7. Ресурсы (системы, файлы, каналы)  
8. Документирование и архивирование  
9. Приложения  

## Поля процесса (SMART / collect)
По каждому процессу должности закрой:

| Поле | Смысл | Пример |
|------|-------|--------|
| `workLocation` / `tool` | Где именно работает исполнитель | «Карточка заседания в 1С, модуль КС» |
| `frequency` / `periodicity` | Как часто | «Каждый рабочий день до 10:00» |
| `trigger` / `triggerAction` | Что запускает действие | «Появление повестки в Outlook» |
| `steps` / `userAction` | Шаги исполнителя | «1. Открыть… 2. Проверить… 3. Отправить…» |
| `actor` | Роль исполнителя | «Помощник ПСД» |
| `roleStatus` | Принадлежность должности | `belongs` / `foreign` / `unclear` |

## Источники фактов (приоритет)
1. **Ответ пользователя** — главный источник по спорным фундаментальным полям.  
2. **Цитаты из materials/** — если в документе явно указано.  
3. **Вывод исследователя (research agent)** — заполняет пробелы, если документ однозначен.

### Фундаментальные поля (конфликт → побеждает человек)
- `roleStatus`, `actor`, `workLocation`, `frequency`, `trigger`, `steps`

### Нефундаментальные (можно брать от исследователя)
- `inputs`, `outputs`, `controls`, `recipients`, `sourceRefs`, уточнения формулировок

## Файлы рабочей области
- `interview.json` — состояние интервью, процессы, knownFacts  
- `materials/*.txt` — тексты загруженных документов  
- `PROCESS_COMPLETENESS.md` — отчёт о полноте (генерируется на этапе material_review)  
- `RESEARCHER_AGENT.md` / `INTERVIEWER_AGENT.md` — роли агентов  

## Критерий готовности процесса к агенту
Все collect-поля заполнены, `roleStatus=belongs`, нет критичных `unknowns`.

## Критерий готовности регламента
- По каждому выбранному процессу есть исполняемый алгоритм в разделе 6  
- Нет заглушек «TBD», «по необходимости» без критерия  
- Документ можно сохранить как `.docx` и передать человеку
